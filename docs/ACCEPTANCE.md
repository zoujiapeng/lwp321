# 验收与提交核对

本项目以完整的小规模业务闭环为验收目标，而不是以界面数量或夸大的并发容量为目标。

默认初始化空业务库和管理员账号。首次改密后，创建教师和学生档案，录入实际谈话要点，按模板生成草稿。人工确认归档后，原始正文和基本信息快照固定；Word使用快照，跟进独立追加。教师与管理员均不能绕过归档后禁止直接改写的业务约束。

## 可复现验证

`cd backend && mvn verify` 执行12项规则单元测试。`python3 tests/integration.py` 在临时H2数据库执行99项检查；连接独立talk_test数据库时执行95项MySQL检查，少4项是H2文件备份恢复不适用于MySQL。`python3 tests/browser_smoke.py` 使用真实Chromium操作页面、下载Word和ZIP、打印PDF并检查手机宽度页面。

测试只使用临时数据库与虚构数据。每次结果在test-results。只有complete为true且所有条目通过，才能描述为该轮验证完成。工作流失败时不能用前半程成功掩盖后续失败。

## 实际使用边界

默认仅监听127.0.0.1，没有内置域名或HTTPS证书。数据库中的正文没有应用层加密，服务器、数据库与备份访问权限必须单独管理。摘要不是电子签名。没有开展校内真实试用、正式安全审计或大规模容量评估。Docker、Nginx和systemd提供配置示例，目标服务器仍需实际验证。

配套DOCX采用标准OOXML、内嵌图片、段落和短表格，并设置必要的防拆分属性。LibreOffice渲染与逐页检查不能称为WPS桌面直接实测。更换字体、软件版本或修改内容后，可能重新分页，应对照PDF再次核对。

## 毕业材料

论文、开题报告、中期检查表以用户提供的三份PDF为版式参考。没有复制模板其他人的姓名、学号、签名和教师意见。身份信息、实际日期、个人实施过程和导师审批由本人核对。材料包含AI工具使用说明，不能隐瞒AI对代码、文字与测试整理的辅助。
